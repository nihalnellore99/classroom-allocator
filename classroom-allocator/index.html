    The problem

    Every course has a class size, a required room type and a fixed time slot. Every room has a capacity and a type. Give each course exactly one room so that:

    • Capacity: the room has at least as many seats as the course has students.
    • Type: labs need a lab, halls need a hall, ordinary lectures can use a lecture room or a hall.
    • No double booking: two courses in the same slot never share a room.

    As a CSP

    ComponentIn this project
    VariablesOne per course, e.g. CS101, MA101, CS102L
    DomainRooms that satisfy the course's capacity and type (unary constraints, applied up front)
    Binary constraintFor two courses in the same slot: room(Ci) ≠ room(Cj)
    SolutionA complete assignment that violates nothing

    Because each course has a fixed slot, slots never interact: the constraint graph is one independent all-different cluster per slot.

    Backtracking

    BACKTRACK(assignment):
  if assignment is complete: return assignment
  c = SELECT-UNASSIGNED-COURSE()
  for each room r in DOMAIN(c):
    if r is consistent with assignment:
      add (c = r) to assignment
      result = BACKTRACK(assignment)
      if result is not failure: return result
      remove (c = r) from assignment      # backtrack
  return failure

    Plain uses a fixed course order (by slot, ordinary lectures first) and only checks constraints when a room is assigned, so mistakes are found late.

    MRV + forward checking always picks the course with the fewest legal rooms left (fail-first), and after each placement removes that room from every unassigned course in the same slot. An empty domain triggers an immediate backtrack.

    Counting effort

    A node is one (course, room) attempt. A backtrack is one attempt that had to be undone. Both are counted exactly as in the report's Python code, and the Solve tab reproduces the report's sample: 138 nodes / 4 backtracks for plain, 24 nodes / 0 backtracks for MRV + forward checking.

    Honest limitations

    • With fixed slots, this exact version is also solvable in polynomial time by bipartite matching. Backtracking is used because it is the course technique and it keeps working when constraints are added that break matching (lecturer clashes, building preferences, slot as a variable).
    • The solver returns the first valid allocation, not the best one, and handles hard constraints only.
    • Worst case is still exponential; timetabling is NP-complete in general (Even, Itai and Shamir, 1976).
